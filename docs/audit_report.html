1. Comprehensive Codebase Inventory

The repository represents a production-grade AI Mock Interview SaaS platform. Below is the audited breakdown across all 20 functional dimensions:

  • 1. Frontend Structure: Next.js 14 App Router, Tailwind CSS design system with custom CSS variables (surface, primary, soft shadows), dark/light mode via next-themes.
  • 2. Interview Configuration UI: app/interview/page.tsx provides step-by-step track selection (Technical Domain, HR Behavioral, Managerial Leadership, Timed Aptitude), Seniority (Junior to Lead), 6 Career Disciplines, and custom focus tags.
  • 3. Interview Room UI: app/interview/[sessionId]/page.tsx delivers an interactive interview room featuring real-time SSE token rendering, auto-scrolling conversation viewport, elapsed timer, dev-mode model telemetry badge, and confirmation end dialogs.
  • 4. Chat & Message Components: components/interview/chat-bubble.tsx (Markdown + syntax-highlighted code rendering via remark-gfm), typing-indicator.tsx (animated TTFT indicator), end-dialog.tsx.
  • 5. Send-Answer Handlers: components/interview/chat-input.tsx (auto-expanding textarea, Enter to send, Shift+Enter for newlines, auto-refocus upon turn completion).
  • 6. API Routes: Standard Next.js Route Handlers (/api/interview/start, /api/interview/[sessionId]/stream, /api/interview/[sessionId], /api/interview/[sessionId]/end, /api/interview/[sessionId]/aptitude/submit).
  • 7. Server Actions: Architecture intentionally relies on REST/SSE Route Handlers for stream compatibility and edge readiness.
  • 8. LLM Integration Architecture: Provider-agnostic factory in lib/llm/index.ts utilizing FallbackLLMProvider for multi-level resilience.
  • 9. Qwen / Groq Configuration: Powered by groq-sdk targeting qwen/qwen3.8-27b as primary model (capped at max_tokens: 200 and temperature: 0.5) for lightning-fast 2–4 sentence turns.
  • 10. Streaming Implementation: HTTP chunked Server-Sent Events (SSE) via Node.js ReadableStream emitting meta, token, done, and error events.
  • 11. Database Schema & 12. Prisma Models: PostgreSQL via Prisma ORM (User, Admin, InterviewSession, InterviewMessage, InterviewReport, Resume, AtsScanLog, LoginLog, PasswordResetToken).
  • 13. Interview / Session Models: InterviewSession (tracks status, type, domain, focusArea, difficulty, score) with one-to-many InterviewMessage[] relations.
  • 14. Authentication / Session Handling: Candidate auth via NextAuth v4 (Credentials + Google OAuth + Speakeasy TOTP 2FA) with strict zero-IP logging. Admin auth is completely isolated via custom HMAC JWT cookies.
  • 15. Existing Prompts: lib/interview/prompts.ts containing dynamic persona injection, 14 Core Behavioral Rules, opening background intro turns, anti-repetition blacklist, and [SESSION_COMPLETED] token handling.
  • 16. Existing Evaluation Logic: services/evaluator.ts (architectural stub) and aptitude/submit/route.ts (objective MCQ scoring).
  • 17. Existing Question Generation: Real-time generative turns guided by domain pillars; curated 40+ MCQ bank in lib/interview/aptitude-bank.ts.
  • 18. Voice / STT / TTS: Modality enum present in schema; audio streaming, STT, and TTS engines are slated for upcoming phases.
  • 19. Fallback & Error Handling: Groq model cascade → Google Gemini provider fallback → Mock provider.
  • 20. Existing Tests: Local LLM evaluation suite in scratch/test-fixes.ts, full TypeScript typecheck, and production Next.js build validation.

4. Database & LLM Engine Audits

Database Audit

The schema cleanly decouples candidate identity, interview sessions, turns, and evaluation reports:

  • Session Lifecycle: Handled by InterviewSession with statuses IN_PROGRESS, COMPLETED, and ABANDONED.
  • Conversation Persistence: Handled by InterviewMessage with role (user, assistant, system) and foreign key to sessionId.
  • Feedback Storage: Handled by InterviewReport storing structured scores, strengths, weaknesses, and improvement tips in JSON fields.

LLM Engine Audit

The LLM engine is optimized for conversational speed and natural cadence:

  • Primary Model: qwen/qwen3.8-27b on Groq. Delivers ultra-low TTFT (~150ms–250ms).
  • System Prompt Constraints: 14 Core Behavior Rules, banned stock clichés ("Understood.", "Let's dive in", "I'm excited to"), strict question anti-repetition list, meta-instruction handling (asking the candidate rather than answering on their behalf), and [SESSION_COMPLETED] conclusion token.

Identified Architecture & Reliability Risks

Key Engineering Considerations
  • Prompt Token Growth: Expanding system prompts with extensive memory and rubrics can inflate TTFT. Must maintain compact, modular prompt injection.
  • Streaming Message Integrity: User messages are saved pre-stream; assistant messages are saved on stream completion. Network dropouts mid-stream require robust reconnect handling.
  • Voice Turn-Taking & Interruption: Live voice requires client-side Voice Activity Detection (VAD) to immediately abort AI audio playback when the candidate speaks.
